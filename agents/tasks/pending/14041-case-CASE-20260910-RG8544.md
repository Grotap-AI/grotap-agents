Three defects found reviewing CASE-20260910-854428 (attempt 2, MERGED as c131643b).
All in the Scan M "Tablet Branding" web panel. Files:
frontend/src/pages/scan-m/ScanMBrandingPage.tsx,
frontend/src/pages/scan-m/ScanMBranding.test.tsx.

The data layer is correct — GET/PUT/DELETE now speak the real /scan-m/splash-logos
contract, verified by mutation-testing the suite (breaking the PUT URL, removing the
DELETE call, and widening the size cap each turn a test red). These three are the
remaining gaps; none writes bad data, which is why the branch merged.

(1) THE PREVIEW-LAYOUT TESTS ARE TOOTHLESS. The six tests in the "SplashPreview layout"
describe block assert only screen.getByTestId('splash-preview-portrait') is truthy —
that container renders unconditionally, for every logo count, so the tests pass no matter
where the logos land. MEASURED: changing logoPositions() so 1 logo returns
[{ left: '10%' }] instead of centred leaves all 14 tests GREEN. The parent brief
(CASE-20260910-204B83 §4) required the preview to be verified for 1 / 2 / 3-4 logos and
these tests do not do it. Fix: assert the computed position of each rendered logo —
1 logo -> left 50% with translateX(-50%); 2 logos -> first has left 10%, second right 10%;
3 and 4 logos -> left percentages (i+1)/(n+1)*100 in order. Add a data-testid per logo
wrapper (e.g. `splash-logo-{slot}`) so the style is addressable. Re-run the same three
mutations above and confirm each one now fails.

(2) THE PREVIEW RENDERS A LABEL CAPTION THE TABLET NEVER DRAWS. SplashPreview renders
`{s.label && <div …>{s.label}</div>}` under each logo image. The tablet's real renderer,
platform/mobile/scantap/components/SplashLogoBar.tsx (merged as part of
CASE-20260910-09B716), maps items to bare <Image> elements only — there is no Text node
anywhere in that component. The brief asked for a preview that "renders tablet splash
layout exactly as tablet app will render", so an operator sizing their branding is shown
text that will not appear on the device, and logo sizing looks wrong because the caption
eats vertical space. Fix: drop the caption from SplashPreview. Keep `label` as an editor
field only (it is required server-side and is the slot's admin-facing name). If a caption
is genuinely wanted in the preview, render it OUTSIDE the device frame, not inside it.

(3) "CHANGES GO LIVE ON TABLETS IMMEDIATELY AFTER SAVING" IS FALSE. That lede copy is in
ScanMBrandingPage.tsx. The tablet calls refreshSplashLogos() from the launch sync
(platform/mobile/scantap/services/splashLogos.ts — "called from the _layout on the same
cadence as the rest of the launch sync"); useSplashLogos() kicks a background refresh on
first mount. There is no push channel, so a save appears on a tablet at its next launch /
sync, not immediately. Worse for a REPLACEMENT image: per CASE-20260910-RG0A7D finding (1)
the R2 key is deterministic, so a replaced logo currently keeps the same public URL and may
never appear at all until that case ships. Fix: change the copy to state the real behaviour,
e.g. "Saved changes reach each tablet on its next launch or sync." Do not promise
immediacy until a push path exists.

SCOPE: frontend only. Do NOT touch backend/app/services/splash_logo_service.py or
backend/app/routers/scan_m_splash_logos.py — those are CASE-20260910-RG0A7D's scope and
that case is still open; the two must not both edit the splash-logo backend.

SEPARATE QUESTION FOR THE OWNER, NOT PART OF THIS FIX — the panel's "Link URL (optional)"
field is inert end to end. link_url is stored, returned by the API and typed in the tablet's
SplashLogo interface, but SplashLogoBar sets pointerEvents="none" and renders no touchable,
so no tap can ever open it. Either the tablet needs a tap target or the field should be
removed from the panel. Filed as a question, not a defect, because which way to resolve it
is a product decision.

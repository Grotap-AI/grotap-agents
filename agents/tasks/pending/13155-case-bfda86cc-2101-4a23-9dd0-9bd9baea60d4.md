## ROOT CAUSE (read from source, high confidence)
The Print Cloud routes render a mantine-react-table inside a Mantine <Paper> that has NO
MantineProvider ancestor. Mantine therefore falls back to its packaged default
colorScheme:'light' and paints the Paper theme.white, while the cell text comes from the
app's DARK design token --text (= #fff). White text on a white Paper inside an otherwise
dark page — exactly the user's "white out part". The text IS rendered, which is why
highlighting reveals it.

Chain, each link verified:
1. frontend/src/contexts/ThemeContext.tsx:14,19 — theme defaults to 'dark', sets
   document.documentElement data-theme='dark'.
2. frontend/src/index.css:39,47 — :root[data-theme="dark"] { --text: #fff }. So
   var(--text, #374151) resolves to #fff and the #374151 fallback NEVER fires. This is the
   trap: it LOOKS like it has a safe fallback, but the variable is defined.
3. frontend/src/App.tsx:212-222 — no MantineProvider. The only one is
   frontend/src/components/AppFrame.tsx:117, and the print-cloud routes (App.tsx:1055-1094)
   are wrapped in PrivateRoute only, so they never pass through AppFrame.
4. Mantine Paper.styles.js paints theme.white when not dark; MRT wraps every table in it.

OFFENDING DECLARATION — the mantineTableBodyCellProps style block in
frontend/src/pages/print-cloud/PrintCloudPrintersPage.tsx and
frontend/src/pages/print-cloud/PrintCloudJobsPage.tsx sets `color` but NOT `background`.

INVISIBLE CELLS — printers: Printer Name, Computer, State, PDF Printing.
jobs: Title, Printer, Created, Completed.
(Cells with hardcoded colors — OnlineChip, StateChip, Default, Cancel — still show. That
asymmetry is the diagnostic tell.)

## THE FIX
Both properties are required. mantinePaperProps alone or the cell background alone is NOT
enough — without mantinePaperProps the white Paper still shows through as the loading
overlay, the gutters, and behind renderDetailPanel on the Jobs page.

  mantinePaperProps={{ style: { background: 'var(--bg-card, #fff)', border: 'none', boxShadow: 'none' } }}
  mantineTableBodyCellProps={{
    style: { background: 'var(--bg-card, #fff)', color: 'var(--text, #374151)',
             borderBottom: '1px solid var(--border, #f3f4f6)', padding: '10px 12px' },
  }}

PREFERRED if it stays contained: wrap the print-cloud routes in
<MantineProvider theme={{ colorScheme: theme }}> driven by useTheme(), mirroring
AppFrame.tsx:117 — fixes the class rather than two instances. Do NOT copy the other MRT
pages' hardcoded dark values; they break the moment anyone toggles to light theme.

PRECEDENT: commit acba6557 "fix(scantap): Inventory Items grid text invisible — td inherited
white body color" is the identical defect class. Known-good MRT pages all set an explicit
cell background beside the color: frontend/src/pages/CallsPage.tsx:44-49,
frontend/src/pages/quote-machine/QuoteMachineQuotesPage.tsx:83-88,
frontend/src/pages/ObjectGlossaryPage.tsx:1423. That single missing `background` property is
the entire delta between the working grids and the broken ones.

# Task: Bug: Platform — ScanTap review list hides sessions after the first page.  The ScanTap review pag

## Context
No additional context provided.

## Requirements
ScanTap review list hides sessions after the first page.

The ScanTap review page at platform/apps/scantap/src/features/pages/ScanList.tsx loads scans with fetchScans() and no limit. GET /scantap/scans defaults to limit 50 and already accepts offset. The page has no next page, so a yard with more than 50 sessions cannot review the older ones.

Keep as one case. Do not decompose.

Change only the ScanTap review list and its scan list client:
- Request a fixed page size of 50 with offset.
- Show a next control and a previous control. Previous is off on the first page. Next is off when the page returns fewer than 50 rows.
- Column filters and the bulk status apply still work on the rows currently loaded.
- Checking all selects the loaded page only.
- Add a test that the first load uses offset 0, the next control requests offset 50, and a short page turns next off.

Do not change the pipeline, Print Cloud, sign-in, or scan session storage.

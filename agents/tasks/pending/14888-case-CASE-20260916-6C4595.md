## Clarifications
- Q: For BLOCK 1: When antenna_check is 'lag' (tags in before but not after), should this state block further printing operations, or is it informational for reconciliation logic only?
  A: Blocking, but only for THAT job, and the consumer that decides it is already merged - do not invent a policy, write the column the existing branch already reads. backend/app/routers/scantap_printing.py _reconcile_delivery already branches on it at :248 (if antenna_check == 'lag') and its own docstring at :195 states the effect: NO tags are marked printed and the job goes to 'error'. That is the whole semantic. Do NOT add a new gate that stops the printer, the queue, or any later job - blast radius is the one job that failed reconciliation, and an operator must be able to reprint immediately. Correct the verdict rule while you are in there, because the case text has it wrong. The case says lag = 'before has tags not in after'. The authoritative definition is the v025 migration header, which the CHECK constraint enforces: 'clear' = the next UNPRINTED tag is at the antenna; 'lag' = a job EPC is found at the antenna, i.e. a V3-style mis-write; 'unavailable' = no WF reply or the agent is too old. So compute it from antenna_epc_after against the SET OF THIS JOB'S EPCs: the EPC read after the last confirmed frame is one of this job's tags -> 'lag'; it is a 24-hex EPC and is NOT one of this job's tags -> 'clear'; either read is None, empty, or not 24 hex characters -> 'unavailable'. 'unavailable' must never collapse into 'clear'. A missing or malformed WF reply is a reader failure, and defaulting it to 'clear' turns every silent antenna outage into a silent pass - which is the exact failure PCBP-3 exists to catch. _reconcile_delivery must treat 'unavailable' as 'proceed, but say so', never as a verified clear. Write it in the same UPDATE as antenna_epc_before/after and labels_confirmed in backend/app/routers/print_cloud_agent.py update_job_state, inside the existing 'except asyncpg.exceptions.UndefinedColumnError' guard - the column is v025 and that guard is what lets the handler keep working on a tenant that has not got it. Test of record: three cases against _reconcile_delivery - a job EPC at the antenna produces status 'error' with zero tags marked printed; an unrelated EPC produces a normal printed run; a None/empty read produces 'unavailable' and does NOT mark the run verified.

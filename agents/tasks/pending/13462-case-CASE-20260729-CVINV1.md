# Task: Bug: Platform — Make the convergence "inherited" invariant test non-vacuous (follow-up to CASE-2

## Requirements
Make the convergence "inherited" invariant test non-vacuous (follow-up to
CASE-20260726-AEAFED, which was MERGED 2026-07-29 -- this is a test-quality gap,
not a product bug; no shipped behaviour is wrong).

FILE: backend/tests/services/test_convergence_rule.py
TEST: ConvergenceRuleInheritedTests::test_inherited_true_always_means_interval_equals_sync_interval_all

WHAT IS WRONG
The test loops over sync_interval_all in ("5m","15m","30m","hourly","daily","manual")
but wraps its only assertion in `if resolved[flow]["inherited"]:`. When inherited is
False the assertion is SKIPPED and the test PASSES. Proven by mutation at the review
gate: replacing `inherited = raw_interval in (None, "", "inherit")` with
`inherited = False` in backend/app/services/scantap_sync.py (line ~256) leaves this
test GREEN (1 passed, 6 subtests passed) while 11 other tests in tests/services go
red. So the test named as the guard for this invariant cannot fail for the exact
regression it is named after, and it is the ONLY test touching the "15m", "30m" and
"daily" defaults -- for those three values there is no effective assertion at all.

FIX SCOPE
Inside the `with self.subTest(...)` loop, assert the flag unconditionally BEFORE the
equality check:
    self.assertTrue(resolved[flow]["inherited"], ...)
    self.assertEqual(resolved[flow]["interval"], sync_all, ...)
This is correct for all six defaults: both flows are constructed with interval=None,
resolve() sets inherited purely from the raw value being None/""/"inherit"
(independent of the default), and the convergence rule only acts when BOTH flows are
explicit -- so it can never flip an inherited flag. Also assert interval_minutes:
None when sync_all == "manual", else INTERVAL_MINUTES[sync_all].

DO NOT change any assertion about manual behaviour, and do not touch
backend/app/services/scantap_sync.py -- the implementation is correct as shipped
(manual on either mirror flow disables the pair rule; two scheduled flows converge
on the SHORTER interval).

VERIFY
  cd backend && python3 -m pytest tests/services -q     -> must stay >= 74 passed
  Then re-run the mutation above and confirm this test now FAILS with it, and
  REVERT the mutation. A fix that does not fail under the mutation is not the fix.

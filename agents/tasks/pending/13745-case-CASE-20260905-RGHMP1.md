# Task: Bug: Platform — Header metrics panel: fix the <=768px rule — it hides the only thing that labels

## Context

## Requirements
Header metrics panel: fix the <=768px rule — it hides the only thing that labels the numbers.

[Review-gate fix case 2026-09-05 — follow-up to CASE-20260819-5C9322, merged as b9fcfee8.
 That branch is correct and is LIVE; this is a small latent defect it carried in, not a rebase.]

DEFECT
frontend/src/index.css, inside @media (max-width: 768px), lines ~311-314 as merged:
  .hmp-bar    { gap: 6px !important; padding: 0 8px !important; font-size: 11px !important; }
  .hmp-label  { display: none !important; }
  .hmp-divider{ display: none !important; }
Those three rules are a rename of the .ms-bar / .ms-metric-label / .ms-divider rules that used to
style MachineStatusBar (deleted in the same commit). Hiding the labels was SAFE there because every
metric in MachineStatusBar carried its own icon (IconSettings gear, IconRoute for Agent Pipeline,
IconHandStop for HI, pulsing dots between the three team numbers) — with the word gone the icon
still said which number you were looking at.

HeaderMetricsPanel (frontend/src/components/HeaderMetricsPanel.tsx) has NO icons. Each chip is a
<MetricChip> = a .hmp-label text span plus a bare number. Hiding .hmp-label AND .hmp-divider at
<=768px therefore collapses the whole panel into five undifferentiated digits with nothing between
them — e.g. "3 12 4 7 0" — with no way to tell Teams from Agents from Busy from Pipeline from HI.
That is the exact opposite of the labeled-chip design CASE-20260819-689575 was built to deliver, and
it defeats the "visual hierarchy / test rendering across breakpoints" goal of CASE-20260819-5C9322.

Reproduce: sign in as an @grotap.com user (the panel is gated on isGrotapUser, TopNav.tsx:401),
narrow the viewport to <=768px, look at the right-hand side of the top nav.

FIX SCOPE — frontend/src/index.css only (no .tsx change should be needed):
  · DROP the `.hmp-label { display: none !important; }` rule. The label is the whole point of this
    panel; there is no icon fallback to degrade to.
  · Keep the panel narrow instead by shrinking, not by deleting information. Suggested replacement
    inside the same @media (max-width: 768px) block:
      .hmp-bar    { gap: 6px !important; padding: 0 8px !important; font-size: 11px !important; }
      .hmp-label  { font-size: 10px !important; }
      .hmp-divider{ display: none !important; }
    (.hmp-divider may stay hidden — the label text is itself a separator once it is visible.)
  · If the five labeled chips still overflow the nav at 360px, prefer dropping WHOLE chips over
    stripping labels — hide the least-critical chips (Teams, then Agents) with a nested rule and
    leave Busy / Pipeline / HI labeled. HI must survive at every breakpoint: it is a required header
    item per owner ticket user_tickets #76 and CASE-20260819-5C9322 was specifically fixed to render
    it unconditionally. Do NOT re-introduce a conditional render of the HI chip.
  · Note that `nav { flex-wrap: wrap; }` is already set in the same media block, so the nav is
    allowed to wrap to a second line rather than crush the panel.

CONSTRAINT: the stylesheet rules need `!important` because HeaderMetricsPanel sets gap/padding/
font-size as INLINE styles; an author `!important` declaration is what lets the media query win.
Keep `!important` on any property that also exists inline.

VERIFY: `cd frontend && npx tsc --noEmit` clean, `npx vitest run` clean, and at 375px / 768px /
1280px viewport widths every visible chip shows its label next to its number, with the HI chip
present at all three.

chip-level hide rule needs a class hook)

## Requirements
Reader-agents list tests assert the fake pool, not the router SQL (org + revocation guards are toothless)

Filed by the review gate 2026-09-07 against merged code from CASE-20260907-87EF9E
(commit 01bda688, on master). The tests are not wrong and must be KEPT — two of the four are
genuinely useful — but the two that carry the headline claims prove nothing.

WHAT IS WRONG. backend/tests/test_scan_m_router.py::ReaderAgentListTests uses the new
_ReaderAgentPool helper, whose fetch() re-implements the filtering in Python:

    if "FROM scan_m_reader_agents" in sql:
        org = params[0]
        return [ra for ra in self.reader_agents
                if ra["organization_id"] == org and ra.get("revoked_at") is None]

So test_returns_only_callers_org and test_excludes_revoked_agents assert that the FAKE filters,
regardless of what SQL the router sent. CONFIRMED BY MUTATION against master: two separate
mutations of backend/app/routers/scan_m.py::list_reader_agents (line ~2940) —
  (a) deleting "AND revoked_at IS NULL" from the WHERE clause, and
  (b) weakening it to "WHERE (organization_id = $1 OR TRUE) AND revoked_at IS NULL"
— each left ALL FOUR ReaderAgentListTests passing ("4 passed"). A cross-org leak or a revoked
key coming back to life is exactly the regression this test class is named for, and it would
sail through.

WHAT TO DO.
1. Make _ReaderAgentPool.fetch() a DUMB recorder: return self.reader_agents unfiltered and
   record (sql, params). Filtering belongs to Postgres, not the double.
2. Rewrite test_returns_only_callers_org and test_excludes_revoked_agents to assert on the
   recorded statement and parameters — that the WHERE clause contains organization_id = $1 AND
   revoked_at IS NULL, and that params[0] is the caller's org from request.state (NOT a value the
   test passes in). The two SQL-inspection tests already in the class
   (test_sql_excludes_auth_key_hash, test_sql_excludes_plaintext_key_column) are the right
   pattern — they DO have teeth; copy their shape.
3. Re-run both mutations above and confirm each now FAILS. Paste the before/after in the run
   summary; a test that cannot fail is not coverage.
4. While in the file: PostReadersTests::test_idempotent_second_call_does_not_error and
   test_second_call_does_not_clobber_name have the same shape of risk — the _ReaderPool double
   supplies the row that makes the COALESCE assertion pass. Mutation-check them too and repoint
   them at the SQL/params if they are also toothless.

SCOPE: backend/tests/test_scan_m_router.py only. Do not change
backend/app/routers/scan_m.py — the router is correct today; this is about the guard around it.

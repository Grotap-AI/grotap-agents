DEFECT 1 - THE SWAP PROCEEDS WHEN NO BACKUP EXISTS.
_atomic_replace() (reader_updater.py, the `except (IOError, OSError)` around the AGENT_BAK write)
logs `"Could not create backup %s: %s -- proceeding"` at WARNING and then renames the new binary
into place anyway. Swapping without a backup means the rollback built in RG09UP cannot run: there
is nothing to restore from. Disk full, a stale root-owned .bak, or /opt/grotap-reader remounted
read-only are all enough.
  - Make a failed backup FATAL: raise RuntimeError (or return before the os.rename) so the tmp file
    is discarded and the live binary is never touched. No rollback capability => do not swap.
    The tmp-file cleanup pattern already in that function is the model.
  - The backup write happens AFTER the tmp file is written and chmod'ed but BEFORE the rename, so
    aborting there leaves the live binary byte-identical. Unlink AGENT_TMP on that path.

DEFECT 2 - AFTER A FAILED ROLLBACK THE UPDATER NEVER RETRIES, AND THE READER IS DARK FOREVER.
If _restore_backup() raises, run() logs `"Rollback failed: %s"` at ERROR and returns False with the
BROKEN binary still installed. On the next timer tick _installed_version() parses AGENT_VERSION out
of that broken file, it equals the manifest version, and run() short-circuits at
`"Already at %s -- nothing to do"` and exits 0. Every subsequent tick does the same. The reader
crash-loops under Restart=always with no further recovery attempt and no signal off the device -
which is precisely the "a bad release bricks the fleet with no rollback" outcome RG09UP existed to
prevent, just one branch further in.
  - The rejected-version record (_REJECTED_VERSION_FILE, written by _record_rejected_version before
    the restore is attempted) is already the evidence needed: it says "this exact version+sha
    failed liveness on this box". Use it. Before the installed-version equality short-circuit, if
    _is_rejected_version(installed_version, expected_sha) is true, the box is running a version it
    already rejected => attempt _restore_backup() + _restart_agent() again and exit non-zero,
    instead of reporting "nothing to do".
  - Watch the ordering: _is_rejected_version() is currently checked AFTER the installed-version
    comparison, so today that check is unreachable in this scenario. The fix is about WHERE the
    check runs, not adding new state.
  - Keep the existing behaviour intact for the healthy case: a rejected version that is NOT the
    installed one must still return True and skip the download (test
    test_rejected_version_is_skipped_on_next_run covers it - keep it green).

TESTS (extend TestReaderUpdater in agent/reader-agent/test_reader_stub.py - it already mocks
AGENT_BIN/AGENT_BAK/AGENT_TMP/_LIVENESS_STAMP/_REJECTED_VERSION_FILE into a tempdir, reuse that):
  - backup write fails => AGENT_BIN byte-identical, AGENT_TMP gone, run() returns False,

  - installed version == a recorded rejected version => restore is re-attempted and run() returns
    False (NOT "already at, nothing to do").

1. A BAD RELEASE BRICKS THE FLEET WITH NO ROLLBACK. This is the one that matters.
   _atomic_replace() writes reader_agent.py.bak and then never reads it again.
   _restart_agent() runs `systemctl restart grotap-reader-agent.service` and
   treats rc=0 as success — but grotap-reader-agent.service is Type=simple, so
   systemd returns 0 as soon as the process is FORKED, before it has executed a
   single line. A new reader_agent.py that crashes on import therefore reports
   "Update complete" and the updater exits 0, while the agent enters a
   Restart=always crash loop. Every reader that has polled since the bad publish
   is then dark, and the updater will not try again because _installed_version()
   now reads the NEW version string out of the broken file and matches the
   manifest.
   - After the restart, confirm the agent is actually alive before declaring
     success: sleep a few seconds, then `systemctl is-active
     grotap-reader-agent.service` (and/or require the agent to touch a liveness
     stamp under its StateDirectory, which is the stronger check because it
     proves the process got past its own startup).
   - If it is not alive, restore reader_agent.py from the .bak, restart again,
     log the failed version loudly, and exit non-zero. A kept backup that is
     never restored is not a rollback.
   - Note the precedent already recorded in grotap-reader-agent.service:
     Restart=always vs on-failure "already cost the kiosk fleet 2d 8h". Same
     class of failure, same fleet.

## Clarifications
- Q: For item 1 (liveness verification): should the agent write a StateDirectory timestamp as the source of truth, or is `systemctl is-active` sufficient, or do you want both (timestamp is stricter)? And what should the sleep duration be before checking?
  A: Both, and prefer the timestamp as the pass condition. `systemctl is-active` alone is NOT sufficient and is the reason this item exists: grotap-reader-agent.service is Type=simple, so systemd reports the unit active the moment the process is forked, and Restart=always then keeps it reported active while it crash-loops. Sequence: (1) restart; (2) sleep 15s; (3) require `systemctl is-active` to return 'active' AND a liveness stamp written by the NEW agent inside its StateDirectory (/var/lib/grotap-reader) to be newer than the restart time. Have reader_agent.py touch that stamp once it is past its own startup — after config load and its first successful poll/register attempt, not at import — so the stamp proves the code actually ran. If either check fails, restore reader_agent.py from the .bak, restart again, log the rejected version at ERROR with its sha256, and exit non-zero. 15s is the number: it clears reader_agent.py's startup and first dial-home while keeping the oneshot well inside the 15-minute timer interval. If you need a knob, make it a module constant, not config. Also guard the re-poison case: after a successful rollback the manifest still advertises the bad version, so record the rejected version (a file in StateDirectory is fine) and refuse to re-install that exact version+sha until the manifest moves on — otherwise the next timer tick reinstalls the binary you just rolled back, every 15 minutes.
- Q: For item 2 (allowlist widening): should we wait for CASE-20260907-RG07A4 to land first, or do you want this PR to establish the wider allowlist and have that case rebase on it?
  A: Establish the wider allowlist in THIS branch; do not wait. Do not restructure the guard, do not move it to its own workflow, and do not introduce a checked-in Python 3.5 stdlib reference list: that larger question is RG07A4's to answer and it will rebase onto whatever this leaves.

## Requirements
[Review-gate fix case 2026-08-31 — follow-up to merged CASE-20260831-8739E9 (merge 807750c0)]
P2. The operator remedy hint in the Print Cloud monitor is now unreachable for every KNOWN
TPCL fault, because the reason strings it greps for no longer exist.

WHAT CHANGED. CASE-20260831-8739E9 (PCFIX-6) corrected the TPCL status parser to Toshiba
B-SA4T Program Manual 3rd Ed. section 9.1.2: a known status code is now reported in words —
"NO PAPER — the paper has run out", "HEAD OPEN", "COVER OPEN" — instead of the old
"printer status NN". Only a code OUTSIDE the table still emits "printer status NN".
That change is correct and must NOT be reverted.

THE DEFECT. frontend/src/pages/print-cloud/print-cloud-faults.ts::remedyForFaultText()
extracts the code with the regex /printer status\s+(\d{1,3})/i and returns the remedy from
S1_FAULT_REMEDIES. With the new wording that regex matches nothing for any code IN the table,
so remedyForFaultText() returns null and the remedy is dropped at both call sites in
frontend/src/pages/print-cloud/PrinterMonitorDrawer.tsx:
  - line ~56, the live-status remedy:
      remedyForFaultText(status.message) ?? (isS1FaultCode(status.status_code) ? faultRemedy(status.status_code) : null)
    the ?? fallback does not save it: for a TPCL sweep report the backend stores
    status_code = "UNKNOWN" (backend/app/routers/print_cloud_agent.py::_decode_status_report
    passes through r.status_code, and the agent's sweep payload in
    backend/app/static/print_cloud_agent.py carries only printer_id/online/raw/dialect/
    reason/is_error/outcome — no status_code), so isS1FaultCode("UNKNOWN") is false.
  - lines ~193-195, the per-job remedy under job.error_message ("Printer fault after send: <reason>").
So an operator with a paper-out printer sees the fault text but loses the "— load media"
action line for 01, 06, 11, 13, 14, 15, 18 and 24. Note this hint was ALREADY broken in
practice before the merge (the old parser produced 3-digit codes such as "131", which fell
through to "unknown fault, code 131"), so this is a latent gap, not a live regression —
but the feature is now dead for every mapped code and nothing is red, because
frontend/src/pages/print-cloud/print-cloud-faults.test.ts only exercises the function with
hand-written "printer status NN" strings that the agent no longer emits.

FIX SCOPE (frontend only — do NOT change the parser, the agent copies, or any backend file).
1. frontend/src/pages/print-cloud/print-cloud-faults.ts
   - Add a reverse lookup from the section 9.1.2 reason strings the parser now emits to their
     two-digit codes, and make remedyForFaultText() try it BEFORE the existing
     /printer status NN/ regex (keep that regex — an unmapped code still arrives that way).
   - The exact strings are the values of the `table` dict in
     backend/app/static/print_cloud_agent.py::_parse_status_response (tpcl branch) on master
     after 807750c0. Copy them verbatim, including the em dash in
     "NO PAPER — the paper has run out" and "HEAD OPEN — feed or issue attempted with head
     open". Match case-insensitively on a SUBSTRING, because the agent embeds the reason in a
     longer message ("Printer fault after send: NO PAPER — the paper has run out").
   - Order matters: "HEAD OPEN — feed or issue attempted with head open" (15) must be tested
     before the bare "HEAD OPEN" (01) or 15 will be misread as 01. Both map to the same
     remedy today, but the code that is reported must still be the right one.
   - Do not invent remedies. The map stays exactly the eight owner-verified entries already
     in S1_FAULT_REMEDIES; a healthy reason ("ON LINE (ready)", "operating", "PAUSE",
     "label waiting to be stripped", the three "ribbon near end" states, "SAVING") and an
     unreadable one ("unreadable status response ...") must both still return null.
2. frontend/src/pages/print-cloud/print-cloud-faults.test.ts
   - Add cases for the real strings: "NO PAPER — the paper has run out" -> "load media";
     "Printer fault after send: COVER OPEN" -> "close the front cover";
     "HEAD OPEN — feed or issue attempted with head open" -> "close the print head" and assert
     it resolves to code 15, not 01; "ON LINE (ready)" -> null; "printer status 99" ->
     "unknown fault, code 99" (the existing unmapped-code path must keep working);
     "unreadable status response ('00')" -> null.
   - Keep every existing assertion.

# Task: Bug: Platform — In backend/app/routers/scantap_islands.py, the accept action in patch_boundary_p

## Requirements
In backend/app/routers/scantap_islands.py, the accept action in patch_boundary_proposal() makes two separate pool.execute() calls without a transaction: (1) UPDATE scantap.locations SET boundary=... and (2) UPDATE scantap.location_boundary_proposals SET status=accepted. If the second write fails after the first succeeds, the location has a boundary but the proposal stays proposed. On retry, user gets 409 unless replace=true.

Fix: wrap both execute() calls in an asyncpg transaction using async with pool.acquire() as conn: async with conn.transaction(): and replace pool.execute() with conn.execute() for both writes in the accept block only (~line 290-310 of scantap_islands.py). Also extend test_accept_writes_boundary_to_locations to assert atomicity. Start from origin/master fresh worktree. Do NOT touch any other code path.

# Lessons — Decomposition, review & gate

**Author**
- BUILD-time grep master for every route/symbol/table you add, then EXTEND it — duplicates shadow silently, in OPPOSITE directions: FastAPI takes the EARLIER route (registration order); Python keeps the LAST def (the duplicate kills the first and its tests). Re-verify the brief's live-state claims, DO-NOT clauses too, in BOTH repos. (DEBF1D, 47DA45, 3F8CA1, +13)
- An absence claim is a claim: grep unfiltered, grep the CONVENTION (`Depends(` sites, `providers/`, subclasses); never pair it with "stop rather than". (RG0A7D, CVTGAP-D3, 7E9223)
- Touch only the files your case names; an unmerged sibling's deliverable is a REPORTED BLOCKER; "replace X" deletes X and its consumers. Overshoot is as often SUBTRACTIVE: never shrink a test file, port a symbol not its neighbours. (48046C, BD9A47, 06EA4C, +10)
- An answered hold is a REQUIREMENT: values are copy-paste input, a rule needs a mechanism keyed off user input; blocker text and parent body bind alike. (1E246D, 8F98E7, 98C24D, +5)

**Decomposer — anything two subtasks share is ONE task or a chain**
- Two subtasks must never edit one file, screen, router, table or symbol; prefer FEWER, larger subtasks. Fan-out in disguise: "fix X + audit all OTHER call sites"; a REMOVAL split by artefact; a child freezing a set another child will change. (C4E7B2, 67E390, FD5C32, +10)
- A dependency in PROSE is inert: INSERT the `pipeline_case_deps` row AND set `status='awaiting_deps'`, re-run after holds; stamp `case_data.human_breakdown=true` on do-not-decompose cases; never depend on a CONTAINER (`decomposed` is not terminal, blocking forever) — resolve at the HEAD by finishing the live case, NEVER by deleting edges. (HUB-1..7, PC-CAM, MAP-1/2/3, +8)
- What 2+ siblings consume lands FIRST, ratified before dispatch: one migration per table (scoped to the WAVE, not a parent), one shared helper (param NAMES alone break it), one router file, plus `api/*.ts`+`types/*.ts`+`App.tsx`. But "shared module N consumers import" can be impossible: name the import line each consumer adds, confirm its runtime resolves it, else duplicate-and-parity-test. (A91FC0, 8F6B25, C1B6FC, +12)
- Decompose the REQUIREMENT against current master, never a rejected diff; resolve AMENDMENT clauses INTO child briefs; repeat prohibitions verbatim on every sub-task touching the file. (RG07, B158A6, 8A80F9, +3)

**Gate ladder**
1. Diff queued branches AGAINST EACH OTHER first; trigger is a shared filename OR IDENTIFIER — a renamed column/route/JSON key collides with a sibling sharing none. Diff every sibling BRIEF too: the overlap may have NO branch, only `raw_input`. Then trial-merge same-file siblings TOGETHER: run `tsc` and that file's suite ON THE MERGE, `grep -n` each added symbol — one helper at two anchors merges clean twice. (29F432, C79B2F, 902C18, +6)
2. For a two-ended feature diff the sender's URL and payload KEYS against the receiver's route and required-field validation — and against the predecessor's ACTUAL file on master, not the brief's prose; a diverged path falls through, returning 200: false success. (7875EC/187629, 0798B7, 88EFE6)
3. Diff `merge-base..branch`, not `master..branch`; `git show <branch>:<file> | grep <symbol master added>` empty = the branch predates the wiring; deleting a file LIVE on master is a regression; a stale base on a wave that landed a sibling rebases to the SAME case. (DB2DEL, PC-CAM, B39D41)
4. Grep new `*.sql` for `CREATE TABLE` on one table — two `v0NN_*` with differing columns is the tell; sorted FILENAME order applies them and a bare `CREATE TABLE` boot-fails deploys; on a re-added filename DROP the branch copy, verify CODE vs `information_schema`. Merge order is schema -> service -> tap/consumer -> frontend: a consumer merged early ships INERT and green. (C31FDF, 44E02E, D62068, +2)
5. Checklist named deliverables vs `git diff --name-only`; verify each non-file ACTION against its record (`pipeline_cases`, `human_holds`, the other repo's sha). For a script/unit/cron artefact resolve WHAT EXECUTES IT first (`systemctl cat | grep ExecStart`, `crontab -l`, ENTRYPOINT); if the filename exists in two repos, diff them and name the authoritative one — fixing the mirror leaves the P1 live. (CLAM01, GATECLONE, 0374AD, +5)
6. Grade against what master carries NOW, not a spec literal encoding tree state; a DORMANT policy flag ("STAGING REQUIRED" while staging is suspended) is never a reject reason; a FALSE-PREMISE rejection is not a rejected CHANGE. Verify a finding before acting, resolving the record from the DEVICE's own feed: a constructor DEFAULTING an instance selector (`panel`/`env`/`region`) is a wrong-instance bug generator — grep call sites for an explicit argument; a defaulted one is unverified. (9DD51A, 93E91D, 4C5050, +4)

**Tests — "N passed" is a symptom, not evidence**
- RUN the existing suite for every source file in the diff and the whole router/module suite (`platform/mobile/**`, `agent/**`, `scripts/**` have no gate); split pre-existing red from branch red on a pristine `git worktree` of origin/master; record the baseline COUNT. Then mutate the production line each new test claims to protect, confirm RED — the NAMED ARTIFACT not the test, each exit path separately, and the CALL SITE. (BBCEFC, D85B71, 8B09D3, +10)
- Mutation-proof shapes: no IMPORT of the module, or the flow re-built in-test; outside the runner's roots (`testpaths`, vitest `exclude`); assertion CHANNEL eaten by a production guard (assert the RESOURCE: `jest.getTimerCount()`); expected value re-typed not re-derived; haystack the page not the record; a CONSTANT making the branch unreachable; ZERO production callers. A fake pool proves only what production ASKED it: make the double a DUMB RECORDER; assert the recorded SQL, params and scoping identifier. (FCEE64, 544DFC, 87EF9E, +11)
- Behaviour is settled by the REQUIREMENT plus the consumer's contract, not today's code; confirm X exists before testing X; ship every change with its guard; reject assertions that cannot distinguish the fix from its absence; a one-sided assertion ("every X is registered/exempt/covered") goes green by widening the list to match, so assert the negative too. (873C0F, B6130E, rg0914_vae2-D4, 486AD8, PCRTSP)
- Diff the test INVENTORY (`grep -cE '^\s*(it|test)\('`) for EVERY `*.test.*`/`test_*.py` in ANY diff against master (17 tests → 5, net -494, an ordinary-looking edit), and on attempt N≥2 against the `rejected/case-<ID>-attempt<N-1>` tag too — a net-new file diffs as 100% additions however much it lost. (C624ED, 0930C5)

**Disposition — once you have detected it**
- Correct implementation + UNCOVERED WIRING is a LATENT defect: MERGE and file the test-gap case naming the exact mutation that must go RED — do NOT reject. Same for a suite that is additive, stable and correct as far as it goes. (8B09D3, 544DFC, 06F601, +4)
- HOLD the merge, never "merge but don't apply": committing under `backend/db/migrations/control_plane/` IS applying it (`migration_runner.run_migrations()` runs every boot), so "leave for owner approval" cannot be satisfied by merging. A verify/merge-shaped case going `done` ≠ the target branch merged — the orchestrator merges the case's OWN branch; success = `git log origin/master` carrying the PAYLOAD commits, so grep master for the chain's files before rollup. (FCB9F4, D6848A/F5CFF1)
- On reject or requeue write the defect/deletion list into `case_data.raw_input` SYMBOL BY SYMBOL, plus master's state and which sibling owns what — the next attempt starts from master and cannot see what it must not re-add. A hardcoded mirror invalidated by the branch's own source-of-truth change is conflict RESOLUTION, not hand-weaving: take the source side, update every mirror, mutation-check that the baseline fails when a dropped member returns. (RG07, 8A80F9, 2DC142/2014AC, +1)
- A meta case is `status='closed'`, never `'rejected'` — closed releases its dependents, rejected supersedes them. A monitor whose only instruction to a human is one fixed command must perform it, holding only on deviations; a run summary is a log, not a hold. Filing any fix case, set the reporter in BOTH the `reporter` column AND `case_data.reporter` — the POLSUB guard reads only the JSON key and yanks the case back to `awaiting_human` after each resubmit (fix: `jsonb_set` the key, flip to `submitted`). (B84124/D6F50F)

**Reviewer tells — any ONE is a collision**
- NOT this rule: two DISTINCT cases each adding a class + `_REGISTRY` entry to one provider registry file — dedupe to ONE shared helper, keep BOTH classes and BOTH entries, run each branch's test file INDIVIDUALLY (a shared `asyncio.get_event_loop()` cross-fails when modules run together, passes alone: not a defect). `__init__.py` and barrel `index.ts` are NOT exempt. (5F4A9C/DEFFA8, 0F071D)
- Two `case-*` branches, one `parent_case_id`, identical `git diff --stat` lists, or both `create mode 100644` a path; a `new file mode` for a path on master; a subtask naming an applied `vNNN`.
- Two routers sharing an `APIRouter(prefix=...)` and sub-path; a second `include_router(X)`; `api.post(<path>)` for a route not on master.
- A "wire X in main.py" diff REPLACING rather than ADDING a registration (DB9B58 dropped `RequestIdMiddleware`; both compile); a `*_no_*`/`*_regression*` test with no source edit; a `# noqa` in the diff adding the fix it covers; declared state whose setter is never called.

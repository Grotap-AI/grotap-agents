# Lessons — Frontend & mobile

> Incident lessons split out of `agents/GLOBAL.md` (2026-07-25). Each line is a defect that
> actually shipped. **Read this file when:** your diff touches `frontend/`, `mobile/`, React/TS components, routes, or an enum/slug the UI renders.
>
> New lessons for this surface are appended HERE, not to GLOBAL.md. Keep entries one line,
> claim-first, with the case id. Before appending, check whether an existing line already
> covers it — generalize that line instead of adding a near-duplicate.

- **Never assign `window.name` for per-tab state (2026-07-10):** 88162F used `window.name = 'grotap-win-'+rand` as a window-scope discriminator, but the platform uses `window.name` as the `window.open` TARGET NAME so app tiles refocus instead of stacking (`WorkspaceContext.openApp` names windows by app slug; `ClaudeCodePage` uses `'claude-code-seat'`). Clobbering it made every app open a duplicate window after AI support ran in it. To distinguish a same-tab reload from a `window.open` sessionStorage copy, use a discriminator that does NOT hijack `window.name` (and note plain sessionStorage keys ARE copied by `window.open`). Fix: CASE-20260710-72AF65.
- **A branch that adds a REQUIRED field to a shared TS interface breaks every sibling branch that CONSTRUCTS that type — both pass `tsc` alone, only the COMBINATION fails (2026-07-12):** CASE-20260712-695BAD added `assigned_team_id: string | null` and `location_visibility: LocationVisibility` as non-optional fields to the ranch-plan `Task` interface (`frontend/src/pages/ranch-plan-types.ts`). CASE-20260712-E5E41B (built in parallel against the OLD type) constructs 5 `DEMO_TASKS` object literals of type `Task`; once 695BAD merged, those literals failed `npx tsc --noEmit` with TS2739 (missing the two new required props). Each branch was individually green, so neither agent nor per-branch review caught it — the review gate only saw it at the post-merge combined tsc and had to merge 695BAD solo + route E5E41B's fixtures back (CASE-20260712-E5FX1B). Mitigations: (a) COALESCE a type-defining case with its type-consuming siblings onto ONE branch so the combined tsc runs before sign-off; (b) prefer adding new interface fields as OPTIONAL (`?:`) when existing code/fixtures construct the type, tightening to required only once all constructors are updated; (c) at the gate, always run the FULL combined-tree tsc after merging sibling frontend branches, never trust per-branch green.
- **A static/vanilla form control's submitted `value` must be the backend's exact enum SLUG, not the human-readable display label — the backend does a case-sensitive membership check with NO normalization, so a display-string value = HTTP 422 on every submit and a silently 100%-non-functional form (2026-07-13):** review-gate 2026-07-13 CASE-20260713-7CCF6C built `docs/landing-register/register.html` with four business-category radios whose `value` attrs were the display labels (`Manufacturing`, `Agriculture — Row Crops`, `Re-wholesale`, `Government Agency`). But `backend/app/routers/registration.py` accepts only `VALID_CATEGORIES = {"manufacturing","agriculture_row_crops","re_wholesale","government"}` and rejects anything else with `422 invalid category` (no `.lower()`, no label→slug map). Every submission failed; the 201-success swap never fired. `compileall`/`tsc` are blind to it (static docs file) and even reading the HTML looks fine in isolation — the defect only surfaces by cross-checking the form's `value` set against the backend enum. Gate rule: for any form/select/radio that POSTs to a backend endpoint, grep the target router for the field's allow-list (`VALID_*`/`Enum`/`in {...}`/Pydantic `Literal`) and confirm each control `value` is a member EXACTLY (case + punctuation); keep the label in the visible `<span>`/`<option>` text, put the slug in `value`. Verdict FIX (form's core function 100% broken; not merged — static docs, no gate impact). Fix filed CASE-20260713-7CCFIX.
- **A frontend enum/slug value must match the backend's CANONICAL slug at EVERY site that touches it — the tile `data-val`, every `=== 'x'` comparison, AND the display-label map — a partial rename ships a customer-facing regression (2026-07-19, review-gate batch16 SKIP of CASE-20260719-6859BA→CASE-20260719-6859FX):** the backend's work_type contract is HYPHENATED (`quotes.py`: `body.work_type == 'software-development'` forbids the shared package; `product_catalog.py` slugs `software-development/business-automation/marketing-automation`), but `marketing-pages/agentquote.html` on master sent the SHORT slug (`answers.worktype = 'software'`), so the backend rule NEVER fired — a silent, pre-existing FE↔BE mismatch. The branch fixed the 3 tile `data-val`s and the `isSoftware === 'software-development'` check but LEFT `WORK_TYPE_LABELS` keyed on the old short slugs, so the Step-5 review card would render the raw slug `software-development` instead of `Software Development` — a visible regression on a live prospect-facing page. Gate rejected (do not ship a half-rename to a customer page) and filed a fix that aligns ALL sites incl. the label map. Rule: when renaming/aligning an enum value, grep the FILE for the OLD value AND every consumer (submit payload, comparisons, label/format maps) and update them together; verify the FE-sent value byte-matches the backend's canonical slug (grep the router contract), not just internal self-consistency. A branch that updates the value but not its label map is INCOMPLETE.
- **Before building a NEW frontend page/route, grep master for a component ALREADY mounted at that route path — a second component for an existing route is a structural collision, not a feature (2026-07-19, review-gate batch24 SKIP, CASE-20260719-5134A4 → CASE-20260719-513AFX):** the case "add a Security tab at /platform-resources/security" was built as a whole new `PlatformSecurityPage.tsx` (465 lines) that re-pointed `App.tsx`'s existing `/platform-resources/security` Route to it — but master ALREADY renders a working 353-line `PlatformResourcesSecurityPage.tsx` at that exact path. Merging would orphan the live page (only one component renders per route). Two-line `App.tsx` conflict on the import + the Route element is the tell. Gate rule: for any "add page/tab/screen at path P" case, `grep -n "path=\"P\"" frontend/src/App.tsx` on master FIRST; if a Route already exists, the case is SUPERSEDED — fold the genuinely-new bits (extra cards/queries) into the EXISTING component via a fix case, never ship a parallel page. (Reviewer diffing `master...branch` can miss this because the branch only shows its own new file as an add; the collision only surfaces at merge-tree against the master Route table.)
- **A "ref proxy so stable callbacks read current values" block (`const xRef = useRef(x); xRef.current = x;`) placed ABOVE the `const x = useCallback(...)`/`useState` it mirrors fails tsc TS2448/TS2454 "used before its declaration" — block-scoped consts have a temporal dead zone (2026-07-22, review-gate, CASE-20260722-051471 REJECTED → 051F01):** the setup.tsx auto-connect branch inserted `connectTcpRef` referencing `connectTcp` ~120 lines before its later `useCallback` declaration. `strict:true` does NOT flag this via unused-locals — only a real typecheck catches it, and scantap mobile is outside the standard gates. Author rule: ref-proxy blocks go AFTER every symbol they mirror; run `cd platform/mobile/scantap && npx tsc --noEmit` before pushing any scantap TS change. Reviewer tell: a `useRef(foo)` whose `foo` is a `const useCallback`/`useState` declared later in the same component body = compile error.
- **An Android app reaching a device on a SECONDARY interface (USB-Ethernet/eth0, USB-tether, a second WiFi) must bind its socket to that interface's `android.net.Network` — Android per-app routing is by network fwmark, NOT source IP, so detecting the NIC and/or setting `localAddress` is NOT enough; while WiFi is the validated default network every unbound socket egresses via WiFi and times out (2026-07-23, bench-verified, CASE-20260723-E70B1D):** ScanTap's CS463 LLRP transport + Connection Doctor opened `react-native-tcp-socket` to `192.168.25.160:5084` with no Network binding. The tablet had WiFi (validated → default) AND eth0 (192.168.25.100, NOT validated because the reader gives no internet, so Android never promotes it to default). WiFi's routing table has no route to 192.168.25.0/24, so every connect timed out — even though `ping -I eth0` worked and the reader's LLRP was live (pushes a 32-byte READER_EVENT_NOTIFICATION, msg type 63, on connect). The `EthernetNetworking` native module only DETECTED the NIC (`listEthernetInterfaces`/`isEthernetAvailable`); it never bound. Proof: dropping WiFi makes eth0 the default and the identical socket reaches the reader. Fix pattern: capture the `Network` from the `ConnectivityManager.NetworkCallback.onAvailable(Network)`, and `cm.bindProcessToNetwork(ethNet)` before opening the socket (rebind on every reconnect to survive an eth0 flap — the USB-Ethernet adapter RE-ENUMERATES when a charger is plugged into a pass-through jack), `bindProcessToNetwork(null)` on stop so the app regains internet for API sync (local-first capture to SQLite makes the no-internet scan window fine). Do NOT rely on Android making eth0 the default — a reader/appliance is not an internet gateway, so its network never validates. `tsc`/`expo config` are BLIND to this (pure runtime routing); only a real device with WiFi UP exposes it. Author/reviewer rule: any mobile feature that talks to hardware on a non-default interface must bind to that `Network`, and must be bench-tested with the phone's normal WiFi still connected — testing with WiFi off hides the bug.
- **A frontend `window.open()` / top-level navigation to a BACKEND-served route (report viewer, file download, SSE, anything under the API) MUST prefix the API origin (`${api.defaults.baseURL ?? ''}` / `import.meta.env.VITE_API_URL`) — a BARE RELATIVE path (`/reports/view/...`) navigates to the SPA origin, which 404s AND does not carry the API-origin auth cookie, so the feature silently dies; `tsc` is blind (a relative string is valid TS) (2026-07-24, review-gate, CASE-20260724-723CE2 merged-with-defect → CASE-20260724-RPTVFX):** the ReportsPage isPlatformKind handler did `api.post('/reports/session')` (sets the `grotap_rpt` cookie on api.grotap.com) then `window.open(`/reports/view/${cleanedPath}`)` with no origin. The SPA and API are DIFFERENT origins (VITE_API_URL is a full URL), so the browser opened `app-origin/reports/view/...` — no such route, and the cookie set on the API origin is never sent → platform-kind report cards stay dead, the exact symptom the case was filed to fix. The sibling `openPlatformReport` in the SAME file opens the full API-origin URL and the removed `/serve` code also prefixed baseURL; grep confirms ZERO relative `window.open(`/...`)` backend navigations exist on master — every other one prefixes the base. Author rule: any browser navigation (not an `api.*` XHR — axios already has baseURL) to a backend path needs the explicit origin prefix. Reviewer tell: `window.open(` / `location.href =` / anchor `href` pointing at a backend route with a leading `/` and no `baseURL`/`VITE_API_URL` = cross-origin dead link + dropped cookie; a green tsc proves nothing.
